皆様、こんにちは。Configuration Manager / WSUS サポート チームです。

本記事では、Configuration Manager のクラウド管理ゲートウェイ (CMG) を作成するときに、Configuration Manager と Azure で行われる処理、およびログの確認方法をご案内します。

仮想マシン スケール セットを使用する CMG を対象に、作成ウィザードの完了から Azure への展開、オンプレミスとの接続確認までを説明します。証明書の発行手順、既存 CMG の移行、およびクライアントのインストール手順は対象外です。

本記事は Microsoft の公開資料を基に説明しており、実ログの抜粋や、実ログによる工程間の対応付けは掲載していません。

## 全体の流れ

1. 作成ウィザードで CMG の構成を指定する
2. サービス接続ポイントが Azure へ CMG を展開する
3. Azure 上で CMG のセットアップを行い、サービスが準備完了になる
4. CMG 接続ポイントを構成し、オンプレミスから CMG への接続を確立する
5. 接続アナライザーで CMG 経由の通信を確認する

作成処理を理解するうえでは、次の 2 つのサイト システムの役割を区別すると、確認する箇所を整理しやすくなります。

| 役割 | CMG に関する主な処理 |
| --- | --- |
| サービス接続ポイント | クラウド サービス マネージャー コンポーネントを実行し、Azure への CMG の展開と監視を行います。 |
| CMG 接続ポイント | オンプレミスから CMG に接続し、CMG が受信したクライアント要求を管理ポイントなどへ中継します。 |

これらの役割と通信方向は、[CMG の計画](https://learn.microsoft.com/ja-jp/intune/configmgr/core/clients/manage/cmg/plan-cloud-management-gateway)および [CMG のデータ フロー](https://learn.microsoft.com/ja-jp/intune/configmgr/core/clients/manage/cmg/data-flow)に記載されています。

## 動作説明の前提

Configuration Manager current branch で、仮想マシン スケール セットとして新規作成する構成を対象とします。バージョン 2203 以降では、新規 CMG の展開方法は仮想マシン スケール セットのみです。

作成前には、Azure サブスクリプション、Microsoft Entra ID との統合、必要な権限とリソース プロバイダー、CMG のサーバー認証証明書、および通信要件を準備します。サービス接続ポイントはオンライン モードである必要があります。具体的な要件は、[CMG の前提条件](https://learn.microsoft.com/ja-jp/intune/configmgr/core/clients/manage/cmg/plan-cloud-management-gateway#prerequisites)をご確認ください。

以降は、これらの準備が完了していることを前提に説明します。CMG のサービスを作成する処理と、そのサービスを介してクライアントを管理できるようにする構成は、別の工程です。

## 各ステップとログの追跡方法

### 関連ログ

| ログ名 | 保存場所・確認先 | 主な用途 |
| --- | --- | --- |
| CloudMgr.log | CMG を管理する最上位サイト (中央管理サイトまたはプライマリ サイト) のサイト サーバーの Configuration Manager インストール先の Logs フォルダー | CMG の展開処理、サービスの状態、および使用状況を確認します。 |
| CMGSetup.log | Azure 上で生成され、オンプレミスのサイト サーバーの Logs フォルダーに同期されます。 | Azure 内で行われる CMG 展開の第 2 段階のセットアップを確認します。 |
| CMGService.log | Azure 上で生成され、オンプレミスのサイト サーバーの Logs フォルダーに同期されます。 | CMG サービスの稼働状況とクライアント要求の処理を確認します。 |
| SMS_Cloud_ProxyConnector.log | CMG 接続ポイントをホストするサイト システム サーバーの SMS\Logs フォルダー | CMG への接続と、CMG とオンプレミスの間の要求の中継を確認します。 |

CMGSetup.log と CMGService.log の実際のファイル名には、サービス名とロール インスタンスの識別子が含まれます。複数の CMG やインスタンスがある場合は、対象のサービスとインスタンスをそろえて確認します。

CMG 側のログは 5 分ごとに Azure ストレージへ送信され、クラウド サービス マネージャーが 5 分ごとに同期するため、ローカルへの反映には最大 10 分の遅延があります。直近の処理を調べる場合は、同期の時間差も考慮してご確認ください。ログ取得のために CMG へリモート デスクトップ接続する方法はサポートされていません。

ログの用途と同期の仕組みは、[CMG のログの監視](https://learn.microsoft.com/ja-jp/intune/configmgr/core/clients/manage/cmg/monitor-clients-cloud-management-gateway#monitor-logs)をご参照ください。

### ステップ 1 : 作成ウィザードで CMG の構成を指定する

管理者が Configuration Manager コンソールの [管理] - [クラウド サービス] - [クラウド管理ゲートウェイ] から作成ウィザードを開始します。

ウィザードでは Azure サブスクリプションや展開方法を選択し、サーバー認証証明書、サービス名、リージョン、リソース グループ、仮想マシンの構成などを指定します。ここで指定した内容を使用して、後続の Azure への展開が行われます。設定項目の詳細は、[Azure で CMG サービスを作成する](https://learn.microsoft.com/ja-jp/intune/configmgr/core/clients/manage/cmg/setup-cloud-management-gateway#set-up-a-cmg)をご参照ください。

ウィザードの完了後に Configuration Manager がサービスのセットアップを開始するため、ウィザードの完了だけでは CMG の展開完了にはなりません。コンソールで対象 CMG の状態を確認し、続けて CloudMgr.log で展開処理の進捗を確認します。

ウィザード内で処理が進まない場合は、その画面のエラーと、選択したサブスクリプションや権限などの前提条件を確認します。

### ステップ 2 : サービス接続ポイントが Azure へ CMG を展開する

サービス接続ポイントは Microsoft Entra ID を使用して認証し、HTTPS で Azure に接続して CMG を展開します。Azure との通信は、オンプレミスのサービス接続ポイントから開始されます。

CMG は仮想マシン スケール セットとして展開され、通常の動作に使用する Azure ストレージ アカウントも作成されます。これらの展開処理を担うのはサービス接続ポイントであり、クライアント通信を中継する CMG 接続ポイントとは役割が異なります。

この段階では CloudMgr.log を中心に、対象サービスの展開が進んでいることを確認します。エラーが記録されている場合は、エラーが示す処理と Azure 側の展開状況を確認し、必要な権限、リソース プロバイダーの登録、およびサービス接続ポイントから Azure への通信要件と照合します。

### ステップ 3 : Azure 上で CMG のセットアップを行い、サービスが準備完了になる

Azure への展開に続いて、Azure 内で CMG のセットアップが行われます。CMG は、指定されたサーバー認証証明書を使用して HTTPS サービスを構成します。

CloudMgr.log に加えて CMGSetup.log を確認すると、Azure 内のセットアップ状況を確認できます。展開処理の調査では、この 2 つのログを組み合わせて、Configuration Manager 側の展開処理と Azure 内のセットアップを分けて確認します。

サービスの準備ができたかどうかは、コンソールで対象 CMG の状態が [準備完了] になったことを確認します。プロビジョニングにかかる時間は指定した設定によって異なります。状態が進まない場合は、CloudMgr.log と、同期済みの CMGSetup.log に記録されたエラーを確認します。

この時点で確認できるのは CMG サービスの準備です。クライアント要求をオンプレミスへ中継するためには、次の CMG 接続ポイントなどの構成も必要です。

### ステップ 4 : CMG 接続ポイントを構成し、オンプレミスから CMG への接続を確立する

管理者がサイト システム サーバーに CMG 接続ポイントの役割を追加し、接続先の CMG を選択します。また、利用する管理ポイントやソフトウェア更新ポイントで CMG トラフィックを許可します。管理ポイントには、クライアント認証方式などに応じた HTTPS または拡張 HTTP の構成が必要です。詳細は、[CMG の設定](https://learn.microsoft.com/ja-jp/intune/configmgr/core/clients/manage/cmg/setup-cloud-management-gateway)をご参照ください。

CMG 接続ポイントは、オンプレミスから Azure 上の CMG へ接続を開始します。CMG がオンプレミスへ新規の受信接続を開始する構成ではありません。CMG 接続ポイントは、接続情報やセキュリティ設定を CMG に公開し、CMG が受信したクライアント要求をオンプレミスのサイト システムへ中継します。

仮想マシン スケール セット構成では、この接続に HTTPS を使用します。必要なポートはインスタンス数などによって異なるため、[CMG のポートとデータ フロー](https://learn.microsoft.com/ja-jp/intune/configmgr/core/clients/manage/cmg/data-flow#ports-and-data-flow)で対象構成の要件をご確認ください。

この段階では SMS_Cloud_ProxyConnector.log を中心に CMG への接続状況を確認し、CMGService.log と併せてサービスの稼働状況を確認します。接続を確立できない場合は、接続先 CMG の選択、CMG 接続ポイントからの名前解決や通信要件、およびログに記録された証明書関連のエラーを確認します。

### ステップ 5 : 接続アナライザーで CMG 経由の通信を確認する

CMG サービスと接続ポイントを構成した後は、コンソールで対象 CMG を選択して [接続アナライザー] を実行します。接続アナライザーは、選択した認証方法で CMG 経由の通信をテストし、結果を表示します。

各テストの結果を確認し、問題がある場合は失敗した項目に沿って確認を進めます。サービスの稼働状況や要求の中継については、CMGService.log と SMS_Cloud_ProxyConnector.log を併せて確認します。

CMG の [準備完了] はサービスの展開状態、接続アナライザーは選択した条件での通信テストの結果を確認するものです。実際のクライアントの利用には、クライアント側の認証、CMG の場所情報の取得なども必要なため、最後に対象クライアントからの通信を確認します。これらの準備は、[CMG 用にクライアントを構成する](https://learn.microsoft.com/ja-jp/intune/configmgr/core/clients/manage/cmg/configure-clients)をご参照ください。

作成後の継続的な監視については、関連記事の [クラウド管理ゲートウェイ (CMG) の監視と運用](20220522_01.md)もご活用ください。
