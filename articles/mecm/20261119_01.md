皆様、こんにちは。Configuration Manager / WSUS サポート チームです。

今回は、Configuration Manager でコンテンツの配布を指示してから、同じサイトの標準配布ポイント (DP) にコンテンツが登録され、コンソールに配布結果が表示されるまでを説明します。特に、サイト サーバーと別のコンピューターにある DP への配布で、ファイル転送、DP 側の登録、サイト側の状態更新をどのログで確認できるかを見ていきます。

DP へのコンテンツ配布は、クライアントが取得できるようにファイルを準備する処理です。アプリケーションやプログラムをコレクションに割り当てる展開とは別の処理であり、配布の成功はクライアントでのダウンロードやインストールの成功を示すものではありません。本記事では、クライアントへの展開や DP の選択、プル配布ポイント、サイト間転送は扱いません。

## 全体の流れ

サイト サーバーとは別のコンピューターにある標準 DP への配布は、次の順に進みます。

1. 配布先を指定し、サイト側のコンテンツ ライブラリに配布元のファイルを用意します。
2. リモート DP 向けの転送ジョブを作成し、必要なファイルを送信します。
3. 転送したファイルをリモート DP のコンテンツ ライブラリに登録します。
4. サイト側で配布結果を処理し、コンソールで対象 DP の状態を確認できます。

## 動作説明の前提

ソース ファイルを持つパッケージの初回配布を例にします。リモート DP とは、同じサイトに属し、サイト サーバーとは別のコンピューターに配置された DP です。事前設定済みコンテンツを使わず、サイト サーバーからファイルを送信する構成を扱います。

サイト サーバーと DP が同居する構成では、両者が同じコンテンツ ライブラリを共有します。このため、リモート DP 向けの転送ジョブや転送先での登録 (ステップ 2 と 3) はなく、PkgXferMgr.log で転送を追う必要はありません。配布処理はサイト サーバーの DistMgr.log、配布結果はステップ 4 に示すコンソールの画面で確認します。

## 各ステップとログの追跡方法

### 関連ログ

| ログ名 | 保存場所 | 主な用途 |
| --- | --- | --- |
| DistMgr.log | サイト サーバーの Configuration Manager インストール先の `Logs` フォルダー | Distribution Manager (DistMgr) によるソース処理、転送ジョブの作成、配布結果の処理 |
| PkgXferMgr.log | サイト サーバーの Configuration Manager インストール先の `Logs` フォルダー | Package Transfer Manager (PkgXferMgr) によるリモート DP への転送、DP 側の登録の呼び出し、結果の通知 |
| SMSDPProv.log | リモート DP (共有パスの例: `\\<DP 名>\SMS_DP$\sms\logs\SMSDPProv.log`) | DP 側のプロバイダーによるコンテンツ ライブラリへの登録 |

本記事では、実ログの抜粋や、実ログを使った工程間の対応付けは掲載しません。実際に確認する際は、対象のパッケージ ID、DP 名、操作した時刻を控えておくと、複数の配布が並行していても同じ配布を絞り込みやすくなります。DistMgr.log と PkgXferMgr.log では、対象の処理を見つけた後、それぞれのログ内でスレッド ID を使うと、同じ処理の前後を確認しやすくなります。

### ステップ 1 : 配布先の指定とサイト側でのコンテンツの準備

コンソールで対象のパッケージを選び、[コンテンツの配布] ウィザードで配布先の DP を指定します。

Configuration Manager は、パッケージに指定されたソース パスからファイルを取り込み、サイト側のコンテンツ ライブラリに格納します。リモート DP に送る際は、このライブラリが転送元になります。DistMgr.log で対象のパッケージ ID を探し、ソースの処理が進んでいるかを確認します。ソース処理の段階でエラーが記録されている場合は、DP への通信を調べる前に、指定したソース パスとサイト サーバーからのアクセスを確認します。

### ステップ 2 : リモート DP への転送ジョブの作成と送信

DistMgr が対象のリモート DP 向けの転送ジョブを作成し、PkgXferMgr がそのジョブを受けて必要なファイルを送信します。パッケージをその DP に初めて配布するときでも、DP のコンテンツ ライブラリに同じファイルがすでにある場合は再利用し、まだないファイルだけを送信します。

DistMgr.log で対象のパッケージと DP の転送ジョブが作成されたことを確認し、次に PkgXferMgr.log で同じ組み合わせの送信処理を確認します。ジョブの作成は転送の完了を示すものではありません。送信が進まない場合は、PkgXferMgr.log で対象 DP への送信要求と、その後の結果を確認します。

### ステップ 3 : リモート DP のコンテンツ ライブラリへの登録

ファイルをコピーした後、PkgXferMgr は Windows Management Instrumentation (WMI) を通じて、DP 側のプロバイダーにファイルをコンテンツ ライブラリに追加するよう指示します。ファイルのコピーが終わった時点では、ライブラリへの登録が完了したかどうかはまだ分かりません。

PkgXferMgr.log で登録の呼び出し結果を確認し、DP 側でファイルがライブラリに追加されたかは、対象 DP の SMSDPProv.log で同じ時間帯の処理を確認します。呼び出しが失敗した場合も、SMSDPProv.log を確認すると、DP 側の処理でどのようなエラーが記録されたかを調べられます。

### ステップ 4 : サイト側での配布結果の処理とコンソールでの確認

PkgXferMgr はリモート DP への配布結果を DistMgr に通知します。DistMgr はその結果を処理してサイト データベースの状態を更新します。PkgXferMgr.log で送信処理の結果を確認できても、コンソールの状態がまだ更新されていない場合は、DistMgr.log で対象のパッケージと DP の結果が処理されたかを確認します。

コンソールでは、[監視] > [配布の状態] > [コンテンツの状態] で対象のパッケージを選び、[状態の表示] を開きます。複数の DP に配布している場合は、パッケージ全体の集計だけでなく、対象の DP の配布状態を確認します。対象の DP が処理中またはエラーの場合は、詳細に表示される状態メッセージを確認し、該当する工程のログと照らし合わせます。

配布結果は、その配布処理の成否を示します。配布後にファイルの整合性を改めて確認する場合は、手動またはスケジュールによるコンテンツ検証を使用します。
