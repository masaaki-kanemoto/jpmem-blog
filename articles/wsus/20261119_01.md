皆様、こんにちは。Configuration Manager / WSUS サポート チームです。

本記事では、Windows Server Update Services (WSUS) の下流サーバーが上流サーバーから更新プログラムの情報 (メタデータ) を同期する流れをご案内します。自律モードとレプリカ モードで何を引き継ぐか、同期の結果と更新ファイルのダウンロード状況をどこで確認するかを説明します。

Configuration Manager のソフトウェアの更新ポイントによる同期や、クライアント スキャンの詳しい調査手順は対象外です。Microsoft Update を直接の同期元にする場合は、[WSUS サーバーと Microsoft Update の同期についての動作説明](https://jpmem.github.io/blog/wsus/20261007_01/) をご参照ください。

## 全体の流れ

上流と下流は、同期元と取得側の関係を表します。下流の WSUS サーバーが上流に接続して情報を取得するため、上流で同期が完了しても、その結果が自動的に下流へ送信されるわけではありません。下流のサーバーで、別の同期が実行されます。

1. 下流の WSUS サーバーが同期を開始する
2. 上流からメタデータを取得し、レプリカ モードの場合は上流の承認とグループの定義も引き継ぐ
3. 下流の WSUS サーバーで同期結果を確認する

## 動作説明の前提

下流の WSUS サーバーで、同期元として別の WSUS サーバーを指定している構成が対象です。下流の [オプション] で、更新元のサーバー名やポートと、上流のレプリカとして動作するかどうかを確認できます。

| 確認する項目 | 自律モード | レプリカ モード |
| --- | --- | --- |
| 更新プログラムのメタデータ | 上流から取得します。 | 上流から取得します。 |
| 更新プログラムの承認 | 上流の承認状態は引き継がず、下流で承認します。 | 上流の承認を引き継ぎます。 |
| コンピューター グループ | 下流でグループを作成し、コンピューターの所属を管理します。 | 上流で作成したグループの定義を引き継ぎます。各コンピューターがどのグループに所属するかは同期されないため、下流に接続するコンピューターの所属は別途設定します。 |

自律モードで独立しているのは承認やグループの管理です。同期元が上流であることは、レプリカ モードと変わりません。

## 各ステップとログの追跡方法

### 関連ログ

本記事では実際のログ抜粋や、ログ行を使った工程の対応付けは掲載していません。同期の成否は下流の WSUS 管理コンソールで確認し、失敗時の調査には次のログを参照します。

| ログ名 | 保存場所 | 主な用途 |
| --- | --- | --- |
| SoftwareDistribution.log | 下流の WSUS サーバーの `%ProgramFiles%\Update Services\LogFiles\SoftwareDistribution.log` | 失敗した同期の時刻を手掛かりに、WSUS が記録したエラーの詳細を確認します。 |

### ステップ 1 : 下流の WSUS サーバーが同期を開始する

同期は、下流の WSUS サーバーで手動操作またはスケジュールによって開始します。手動で実行する場合は、WSUS 管理コンソールで下流のサーバーを選択し、[概要] の [同期の状態] から [今すぐ同期] を選択します。自動で実行する場合は、下流の [オプション] にある [同期スケジュール] を確認します。

下流で新しい更新プログラムを受け取るには、上流がその更新プログラムの情報を取得済みである必要があります。定期運用では、上流の同期が終わった後に下流が同期できるよう、両方のスケジュールをご確認ください。

### ステップ 2 : 上流からメタデータを取得し、レプリカ モードの場合は上流の承認とグループの定義も引き継ぐ

WSUS の階層では、最上位の WSUS サーバーで選んだ製品と分類が、同期対象の基準になります。下流は、接続先の上流が提供できる範囲のメタデータを取得します。下流に目的の更新プログラムが見当たらない場合は、まず接続先の上流にその更新プログラムがあるかを確認します。上流にもなければ、最上位の [製品と分類] や、上流側の同期結果をご確認ください。上流にない更新プログラムを、下流の設定だけで取得することはできません。

更新プログラムの言語も上流の設定が上限です。たとえば、上流で日本語と英語を対象にしている場合、下流では日本語だけに絞れます。一方、下流で必要になった言語が上流の対象外であれば、上流の設定から見直します。

メタデータが表示されることと、その更新プログラムが承認されていることは別です。自律モードでは下流の承認を、レプリカ モードでは上流の対象グループへの承認と、それを反映する下流の同期結果を確認します。

### ステップ 3 : 下流の WSUS サーバーで同期結果を確認する

下流の WSUS 管理コンソールで同期の履歴を表示するノード (英語 UI では [Synchronizations]) を開き、対象の実行日時の結果が成功であることを確認します。失敗した実行を選択すると、同期の詳細からエラーの説明を確認できます。必要に応じて、その実行時刻の SoftwareDistribution.log を参照します。接続に関するエラーの場合は、下流に設定した上流のサーバー名、ポート、プロキシ設定を確認します。

## 同期後に別途確認する項目

下流の同期が成功しても、更新ファイルのダウンロードが完了したことや、クライアントが更新プログラムを検出したことまでは確認できません。

更新ファイルを下流の WSUS サーバーに保存する構成では、下流は通常、ファイルを上流から取得します。設定によっては、下流がファイルを Microsoft から直接ダウンロードしますが、この場合もメタデータの同期元は上流のままです。遅延ダウンロードが有効な場合は、先にメタデータを同期し、ファイルは承認後にダウンロードします。

更新ファイルを WSUS に保存しない構成では、承認された更新プログラムのファイルをクライアントが Microsoft Update から取得します。この場合も、下流がメタデータを同期する相手は上流の WSUS サーバーです。

| 確認したいこと | 確認箇所 |
| --- | --- |
| 下流が上流と同期できたか | ステップ 3 のとおり、下流の WSUS 管理コンソールで対象の同期結果を確認します。 |
| 更新ファイル本体を下流の WSUS サーバーから配布できる状態か | ファイルを下流に保存する構成では、下流の更新プログラム一覧の [ファイルの状態] 列で、ファイルのダウンロードが完了しているかを確認します。 |
| クライアントが更新プログラムを検出できたか | クライアントに設定された更新サービスを確認し、クライアント側でスキャン結果を確認します。WSUS サーバー間の同期履歴は、クライアントがスキャンしたことを示すものではありません。 |

ファイルの確認方法は、[WSUS の仕組み ダウンロード編](https://jpmem.github.io/blog/wsus/2022-06-06_01/) もご参照ください。
